# 自瞄作业二：运动解算

本项目使用 C++17、OpenCV 和 YAML 实现前哨站视频中的灯带检测、装甲板跟踪及短时运动预测。输入采用视频文件，画面通过 `cv::imshow` 显示，不启动相机或控制硬件。

工程参考 [TongjiSuperPower/sp_vision_25](https://github.com/TongjiSuperPower/sp_vision_25) 的检测、观测几何和目标状态分层思路，将视频读取、检测、关联、估计和绘制分别实现。

## 一、处理流程

程序逐帧读取视频及对应时间，经过图像预处理、灯带提取和配对后，得到装甲板实测中心与四边形。跟踪器完成观测关联、状态更新和未来位置预测，最后将结果叠加到原画面，并保存运行日志。

默认按帧号和视频帧率计算时间；配置 `input.timestamp_file` 后，改为读取逐帧时间戳。时间戳必须连续对应解码帧，时间严格递增。配置 `input.prefetch_frames` 可以启用有界读取队列，队列满时等待，不丢帧。

## 二、灯带检测与四边形构造

传统检测使用亮度和颜色差阈值提取亮区，再按轮廓面积、长度、宽高比和倾角筛选灯带。每根灯带保存长轴、宽度、端点和顶点。

左右灯带通过长度比例、角度差、间距及上下错位约束进行配对。四边形按 `TL、TR、BR、BL` 排列，并检查凸性、面积和灯带包含关系。显示框由灯带外缘构造，因此可以随灯带倾斜形成梯形，不强制使用规则矩形。

显示外扩角点和用于几何解算的灯带中心线端点分别保存，修改显示边距不会改变运动测量。单灯带不能生成完整的实测装甲板框；不合法或归属有歧义的配对不作为接受观测。

可选 `neural_supported` 后端通过网络提供候选和类别，再匹配真实灯带。局部重提取开启时，在候选区域内重新寻找灯带，最终观测仍由像素支持的灯带端点构成。

## 三、二维跟踪与预测

### 观测关联

跟踪器为每条局部轨迹分配递增 ID。关联使用预测中心距离、灯带几何和归一化创新，并执行一对一分配。连续有效观测达到确认帧数后，轨迹进入已确认状态。

新生轨迹在确认前可以显示当帧接受的绿色观测框，标注 `T{id} tentative obs`，但不输出未来框，也不参与三槽位身份解算。确认后由已确认轨迹接管绘制，不重复显示。

### 位置与速度估计

X、Y 两轴分别使用位置—速度卡尔曼状态，根据帧间时间进行预测，再用接受观测更新。测量噪声、加速度噪声、初始速度方差和关联门限均从 YAML 读取。

默认视频配置还启用多帧中心预测融合：

1. 收集最近 9 次连续、已确认的实测中心。
2. 使用实际时间间隔做线性拟合，得到二维速度。
3. 用当前实测中心加上“拟合速度 × 预测提前量”，得到另一组未来中心。
4. 将其与卡尔曼预测按配置比例融合，默认各占 0.5。

拟合最短时间跨度默认为 0.20 秒，最大相邻间隔为 0.10 秒。历史不足或身份存在歧义时不启用融合；缺测会清空拟合历史，恢复后重新积累。预测只使用当前及过去观测，不使用整段视频预学习轨迹、未来帧或固定角速度。

未来位置的不确定度同时考虑测量与拟合速度的相关性、两个预测的相关性及其差异，并保留原滤波协方差下限。未来四边形按预测中心整体平移，不单独外推四个角点，避免收窄时发生角点交叉。该二维模型不输出物理角速度，平移框也不表示已恢复三维透视形变。

### 遮挡与短时丢失

未接受观测时，内部状态在配置期限内继续推算。是否绘制与是否存在内部预测分开判断：缺少灯带支持时不绘制完整跟踪框，默认没有接受观测时也不绘制未来框。超时轨迹被移除；关联歧义需要后续连续有效观测重新确认。

三槽位模块根据局部轨迹的观测特征和访问顺序维护身份假设。槽位编号与局部 ID 分开记录，不将尚未确认的槽位关系表示为永久实体身份。

## 四、画面叠加

- 绿色：当前接受的双灯带观测。
- 橙色：具有可见灯带支持的短时跟踪框。
- 红色：通过历史、身份、时间范围及不确定度检查的未来框。

画面同时显示编号、跟踪状态和预测提前量。`display.enabled: true` 且未传入 `--headless` 时调用 `cv::imshow`，按 ESC 结束运行。

## 五、三维模式

工程通过估计器接口区分 `image_2d` 和 `calibrated_3d`。三维模式使用实测灯带中心线端点进行 IPPE 位姿求解，再结合旋转轴、灯带俯仰和三块装甲板几何建立共同中心与相位模型。通过有限历史窗口的鲁棒拟合估计中心速度和角速度，预测后重新投影到图像。

三块板的相位间隔为 120°，各板高度偏移由配置给出。位姿多解、重投影误差、联合关联和身份歧义分别检查。相位、速度、中心及角点不确定度参与预测有效性判断；等价身份假设未消除时不输出可信身份预测。

三维标定参数集中在 `config/calibrated_video.template.yaml`：

- 相机内参、畸变系数和标定分辨率。
- 目标轴坐标系到相机坐标系的旋转矩阵。
- 灯带长度、左右灯带中心距、旋转半径和装甲板俯仰角。
- 三块装甲板各自的高度偏移。

开启去畸变时，检测与估计使用同一去畸变图像，投影使用对应内参和零畸变，避免重复校正。本次输入视频未取得对应标定，因此采用二维模式；三维模板中的未知参数保留为空，缺少必要参数时程序拒绝启动三维模式。三维目标模型限定三块板，二维槽位数量配置不改变这一结构。

## 六、参数配置

`config/video.yaml` 为本次视频的默认配置，主要分为：

- `input`：视频路径、时间戳和读取队列。
- `detector`：亮度、颜色、灯带几何、配对及显示外扩参数。
- `tracking`：滤波噪声、关联、确认、漏检期限及中心预测融合。
- `prediction`：预测提前量。
- `target_slots`、`visibility`：二维槽位关系及绘制所需的灯带支持。
- `geometry`、`rigid_estimator`：相机标定、实体尺寸和三维估计参数。
- `display`：画面显示开关。

程序逐帧检查配置变化。非法数值、未知字段和重复键会被拒绝，并保留原配置。预测提前量、显示和传统阈值支持热更新；当前模型使用的关联、几何和估计参数变化时清空不兼容状态。输入文件、估计模式和检测后端等变化需要重新启动。未启用的参数仍进行校验，但不影响当前模型状态。

## 七、代码结构与运行

`src/core.cpp` 负责配置和输入，`src/detector.cpp` 负责灯带检测，`src/tracker.cpp` 负责二维关联与状态估计，`include/center_forecast.hpp` 实现中心拟合与预测融合，`src/target_slots.cpp` 维护槽位假设，`src/rigid_estimator.cpp` 实现三维估计，`src/video_runner.cpp` 串联流程并绘制结果。

依赖 C++17、CMake、OpenCV 4 和 yaml-cpp；网络后端另需 OpenVINO。虚拟机中运行：

```bash
cd /home/rm/robotmaster/07_armor_motion
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j4
./build/outpost_video config/video.yaml --no-video
```

无图形显示时使用：

```bash
./build/outpost_video config/video.yaml --headless --no-video
```

输入路径由 YAML 指定。程序为每次运行创建独立结果目录，`--output-dir 新目录` 可指定位置，不覆盖已有结果。`--no-video` 关闭视频保存；不传该参数时生成 `tracking-preview.mp4`。

运行日志分别记录检测候选、关联原因、跟踪状态、槽位、预测不确定度及绘制状态。`tentative_observations.csv` 保存暂定观测，`shape_reliability.csv` 中的 `center_forecast_blended` 标记是否使用中心预测融合。三维状态使用独立日志，避免与二维量混淆。程序同时保存生效配置及变更事件，输出检查完成后将运行状态标记为 `completed`。
