# 第五次作业：并发传感器数据处理与时间同步

## 项目简介

本程序使用两个生产者线程分别读取相机和 IMU 文本数据，并通过同一个有界线程安全队列把数据交给消费者线程。消费者按传感器类型保存数据，最后为每个相机包匹配时间戳最接近的 IMU 包。

程序使用 C++17，并使用了 `std::thread`、`std::mutex`、`std::condition_variable` 和 `std::atomic`。

## 编译与运行

运行公开样例验证：

```bash
bash verify_sample.sh
```

手动编译和运行：

```bash
cmake -S . -B build
cmake --build build -j
./build/sensor_sync config/sensor_sync.conf
cat data/result.txt
```

配置文件中的相对路径以配置文件所在目录为基准。程序会拒绝未知键、重复键、缺失键和非法数值。

## 输出示例

```text
CAMERA 0 IMU 0 DELTA 200
CAMERA 1 IMU 2 DELTA 100
```

## 问题回答

### 1. 队列已满或为空时，线程如何进入等待状态？

队列满时，生产者调用 `not_full_.wait(lock, predicate)`；队列空时，消费者调用 `not_empty_.wait(lock, predicate)`。`wait` 会原子地释放互斥锁并让线程休眠，被唤醒后重新取得互斥锁并检查条件。这样不需要循环占用 CPU，也能用谓词应对虚假唤醒。

### 2. 如何判断最后一个生产者已经结束？

程序使用初始化为 2 的 `std::atomic<int> producers_remaining`。每个生产者结束时执行 `fetch_sub(1)`；如果返回值为 1，说明当前线程是最后结束的生产者，它负责调用 `queue.close()`。

### 3. 为什么关闭队列后仍然需要允许消费者读取剩余数据？

关闭队列只表示不会再写入新数据，不代表队列中已经存在的数据无效。如果关闭后立即停止读取，会丢失尚未消费的数据。因此 `pop` 在“队列已关闭但仍有数据”时继续返回数据，只在“队列已关闭且为空”时返回 `false`。

### 4. 时间戳匹配算法的流程和复杂度是什么？

先分别按“时间戳、序号”排序相机与 IMU 数据。对相同时间戳的 IMU，只保留序号最小的一个。随后使用单调向前的双指针，对每个相机包只比较它时间戳左右两侧的两个 IMU 候选项。

排序复杂度为 `O(C log C + I log I)`，双指针扫描复杂度为 `O(C + I)`，总复杂度符合题目要求：`O(C log C + I log I + C + I)`。

### 5. 如何处理时间差相同、时间戳相同等边界情况？

时间差相同时选择时间戳更早的 IMU；IMU 时间戳也相同时选择序号更小的包。相机结果按时间戳升序输出；相机时间戳相同时按序号升序输出。若最小时间差大于 `max_delta_us`，输出 `UNMATCHED`。

### 6. 如果某个生产者读取文件失败，如何保证其他线程正常退出？

生产者捕获异常后，在互斥锁保护下保存第一个 `std::exception_ptr`，随后关闭队列。关闭操作会唤醒等待中的生产者和消费者：另一个生产者的 `push` 返回 `false` 后结束，消费者继续排空队列并在队列为空后退出。主线程 `join` 所有线程，再重新抛出保存的异常，打印错误并以非零状态退出。
